# AI Bots

**いつものチャットに、あなただけのAIボットを。**

AI Botsは、SlackやMicrosoft Teamsなどで動くAIボットを作り、運用するためのセルフホスト型Webワークスペースです。  
データベースや認証情報を自分の管理する環境に置き、組織のセキュリティ要件に合わせて運用できます。  
モデルを選ぶだけでなく、ファイルや外部サービスへのアクセス、コード実行、定期実行、利用量の上限まで、ボットごとに設定できます。

## こんなことができます

| やりたいこと                         | AI Botsでの構成例                                                                                          |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| チームの質問にチャット上で答える     | SlackまたはTeamsのアダプタとAIエージェントをボットに割り当てる。会話履歴やボットの指示を設定する。         |
| 資料を探して会話に活かす             | Google Driveの認証情報やOpenDAL対応ストレージの接続情報を設定し、ボットにファイルツールを割り当てる。      |
| 毎朝、決まったスレッドに情報を届ける | ボットとスレッドを対象に、タイムゾーン付きのCronスケジュールでプロンプトを実行する。                       |
| チャットからファイルを扱う           | 添付ファイルの読み取り、ファイルの投稿、必要に応じたサンドボックスでのコード実行を組み合わせる。           |
| 利用範囲を管理する                   | ボット・エージェント・プロバイダー単位の利用量の上限と、ユーザー・グループ単位のリソース権限を設定する。 |

たとえば「平日の朝にチームのスレッドへ定例の確認項目を投稿する」ボットなら、**チャットアダプタ → AIエージェント → ボット → スケジュール**の順に設定します。Google DriveやMCPサーバーを追加すれば、同じボットに必要な情報源も渡せます。

## 主な機能

- **チャットボット:** 指示プロンプト、失敗時メッセージ、会話履歴、稼働状態、利用するサービスを設定できます。パブリックIDの確認・再生成や、アダプタごとのWebhook URLの確認・コピーにも対応します。
- **チャットアダプタ:** Slack、Microsoft Teams、Google Chat、Discord、X、LINEに接続できます。プラットフォーム固有の設定、OAuth認証情報の紐付け、接続テストを行えます。
- **AIプロバイダーとエージェント:** OpenAI、Azure OpenAI、Anthropic、OpenAI互換プロバイダーを設定し、モデルIDとモデルオプションを指定したエージェントを作成できます。ボットに割り当てる前にエージェントをテストできます。
- **ツールとファイル:** チャット・添付ファイル用ツール、Google Drive、OpenDAL対応のリモートファイルストレージ、King of Timeの勤怠データをボットに利用させることができます。利用可能なツールは、ボットの設定と接続済みの認証情報によって異なります。
- **Web検索とメモリ:** SearXNGを設定するとWeb検索を利用できます。ボットのメモリは無効・スレッド別・ボット全体で共有から選べます。
- **MCPサーバー:** MCPエンドポイントとHTTPヘッダーを設定し、接続テストを行って、ボットから利用できるようにできます。
- **サンドボックス:** E2BまたはOpenSandboxの実行環境を設定できます。環境変数、許可するネットワークドメイン、初期化コマンド、共有範囲を管理できます。永続インスタンスの確認や内蔵ターミナルの利用にも対応します。
- **スケジュール実行:** 5フィールドまたは6フィールドのCron式とIANAタイムゾーンを指定し、選択したボット／アダプタのスレッドでプロンプトを実行できます。スケジュールの変更は実行中のスケジューラーに反映されます。
- **利用状況と利用量の上限:** ダッシュボードで直近30日間のリクエスト数やトークン利用量を確認できます。ボット、エージェント、プロバイダーごとに利用量の上限を設定し、スレッドごと／対象全体の集計や、Cron式とタイムゾーンによる集計期間のリセットを指定できます。上限到達後のリクエストには設定したメッセージを返します。
- **実行履歴:** チャットとスケジュールによるボット実行の状態・時刻・失敗理由を確認できます。ダッシュボードには直近24時間の失敗を表示し、実行履歴画面ではボット・状態・期間で絞り込めます。閲覧できる履歴はボットのアクセス権に従います。
- **グループと権限:** 管理者はグループのメンバーを管理し、ボットなどのリソースへのアクセス権を設定できます。
- **一覧の検索:** 管理画面の一覧は名前などで検索でき、25件ずつページを切り替えられます。検索とページ分割はサーバー側で行います。
- **OAuthとユーザー:** 連携サービスのOAuth認証、ユーザー管理、TOTPによるMFA、メールアドレス検証とパスワード再設定に対応します。詳しくは[ユーザーと認証](#ユーザーと認証)を参照してください。

## カスタマイズ

標準で対応していないサービスや実行環境が必要になったら、対応するインターフェースを実装して組み込めます。まず既存の実装を手本にしてください。OpenAI互換APIなら、独自プロバイダーを実装せずに「OpenAI Compatible」を設定する方法もあります。

| 拡張したいもの         | インターフェースと実装例                                                                                                                                        | 組み込み位置                                                                               |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 非対応のチャット       | Chat SDKの `Adapter` を実装。[Slackアダプタの組み込み例](./app/.server/features/chat-adapter.ts)                                                                | 同じファイルの `ChatAdapterFactory` / `FACTORIES` に追加。                                 |
| 非対応のAIプロバイダー | `ModelFactory`。[OpenAIの実装例](./app/.server/features/provider.ts)                                                                                            | 同じファイルの `FACTORIES` に追加。                                                        |
| 新しいサンドボックス   | [`Sandbox` インターフェース](./app/.server/features/toolsets/sandboxes/index.ts)と[E2Bの実装例](./app/.server/features/toolsets/sandboxes/e2b.ts)               | `sandboxes/index.ts` の `SANDBOXES` に追加。                                               |
| メモリの保存先         | [`FileSystem` インターフェース](./app/.server/features/filesystem/index.ts)と[OpenDAL の実装](./app/.server/features/filesystem/opendal.ts)                     | [ボットの処理](./app/.server/features/bot.ts)で `OpenDalFileSystem` の生成箇所を差し替え。 |
| メールの送信方法       | [`EmailProvider` インターフェース](./app/.server/features/email-providers/index.ts)と[SMTPリレーの実装例](./app/.server/features/email-providers/smtp-relay.ts) | `email-providers/index.ts` の `getEmailProvider()` で選択。                                |
| 新しいツールセット     | [`ToolSetFactory` インターフェース](./app/.server/features/toolsets/index.ts)と[Google Driveの実装例](./app/.server/features/toolsets/gdrive.ts)                | `toolsets/index.ts` の `getToolSetFactories()` に追加。                                    |

ファイルシステムはボットのメモリと一時ファイルの保存に使われています。チャットの添付ファイルやGoogle Driveなどの外部ファイル連携は、別のツールとして実装されています。

## 動作要件

- Node.js 24 以降
- PostgreSQL 15 以降
- npm

同梱のCompose設定ではPostgreSQL 16を使用します。オプションの連携先としてSearXNGとOpenSandboxも定義されています。

## セットアップ

1. 依存関係をインストールします。

   ```bash
   npm ci
   ```

2. リポジトリのルートに `.env` を作成し、データベースURLと暗号化キーを設定します。

   ```dotenv
   DATABASE_URL="postgresql://user:password@localhost:5432/mydb"
   CREDENTIALS_ENCRYPTION_KEY="<base64でエンコードした32バイトのキー>"
   ```

   キーは次のコマンドで生成できます。

   ```bash
   openssl rand -base64 32
   ```

   キーは秘密情報として安全に保管し、継続して同じ値を使用してください。保存済み認証情報の暗号化に使われるため、変更すると既存の暗号化済み認証情報を復号できなくなります。

3. PostgreSQLを起動します。同梱のComposeサービスを使う場合:

   ```bash
   docker compose --env-file .env -f infra/compose.yaml up -d postgres
   ```

   データベースが正常起動したことを確認し、初回のみテーブルを初期化します。

   ```bash
   npx prisma db init
   ```

4. アプリを起動します。

   ```bash
   npm run dev:app
   ```

   `http://localhost:5173` を開き、初回アクセス時に最初のユーザーアカウントを作成します。`npm run dev` はアプリに加えて、`CLOUDFLARE_TOKEN` が設定されている場合にCloudflare Tunnelも起動します。Tunnelを使わないローカル開発には `npm run dev:app` を使用してください。

## 最初のボットを動かす

1. **AIプロバイダー**で利用するモデルの認証情報を登録し、**エージェント**でモデルIDを指定します。エージェントのテストで応答を確認します。
2. **チャットアダプタ**でSlackなどの接続情報を登録し、接続テストを行います。
3. **チャットボット**を作成し、エージェントとアダプタを割り当てます。たとえば指示に「質問には簡潔に答え、分からないことは推測せずに伝える」と入力します。
4. ボットの一覧から該当アダプタの**Webhook URL**をコピーし、チャットプラットフォーム側に登録します。外部サービスからWebhookを受ける場合は、アプリに到達できる公開URLが必要です。
5. 接続したチャットでメッセージを送り、応答を確認します。必要に応じて、ボットのツール、MCPサーバー、メモリ、スケジュールを追加します。

アダプタごとの認証情報やWebhookの登録方法は、各プラットフォームの設定に従ってください。ローカル環境を外部から受けられるようにする場合は、同梱のCloudflare Tunnel設定も利用できます。

## ユーザーと認証

OAuthクライアントを管理し、連携サービスのアカウントを認証できます。ログインページから最初に登録したユーザーは管理者になります。ユーザーアカウントの管理と管理者権限の付与・解除は管理者のみが行え、管理者は常に1人以上必要です。

管理者向け設定画面からMFAの必須化、セッション持続時間、ログイン失敗の上限回数を指定できます。上限回数ログインに失敗したユーザーはロックされ、ユーザー一覧から解除できます。MFAには認証アプリのTOTPを使用し、ユーザー一覧から個別のMFA設定をリセットできます。

標準実装のメール送信にはSMTPリレーを使用します。送信先を設定すると、初回管理者の作成時とユーザーの作成・メールアドレス変更時に検証メールを送信できます。検証済みユーザーはログイン画面からパスワード再設定メールをリクエストでき、リンクは1時間有効です。未検証メールへの再送はユーザー一覧から行えます。SMTPリレーの設定例は [`.env.example`](./.env.example) を参照してください。

## 環境変数

| 変数                         | 必須         | 用途                                                                                                                                                                                                   |
| ---------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `DATABASE_URL`               | 必須         | アプリとチャット状態ストアが使用するPostgreSQL接続文字列。                                                                                                                                             |
| `CREDENTIALS_ENCRYPTION_KEY` | 必須         | 認証情報の暗号化とOAuth認可状態の署名に使用する、Base64形式の32バイトキー。                                                                                                                            |
| `OAUTH_BASE_URL`             | OAuth利用時  | OAuthコールバックURL `/oauth/callback` の生成に使う公開HTTPSオリジン（パスなし）。ローカル開発では `http://localhost` も使用できます。生成されたコールバックURLをOAuthプロバイダーに登録してください。 |
| `PUBLIC_APP_URL`             | 任意         | Webhook URL、メール検証リンク、一時ファイルのダウンロードリンクの生成に使う公開アプリURL。未設定時はリクエストのオリジンを使用します。                                                                 |
| `E2B_API_KEY`                | E2B利用時    | E2Bサンドボックスプロバイダーを有効にします。                                                                                                                                                          |
| `OPEN_SANDBOX_DOMAIN`        | 任意         | OpenSandboxを有効にし、接続先ドメインを指定します。                                                                                                                                                    |
| `OPEN_SANDBOX_API_KEY`       | 任意         | 同梱Compose設定でOpenSandboxサーバーに渡すAPIキー。                                                                                                                                                    |
| `SEARXNG_URL`                | 任意         | Web検索ツールが使用するSearXNGのエンドポイント。                                                                                                                                                       |
| `SMTP_RELAY_HOST`            | メール利用時 | SMTPリレーのホスト名。                                                                                                                                                                                 |
| `SMTP_RELAY_PORT`            | メール利用時 | SMTPリレーのポート番号。                                                                                                                                                                               |
| `SMTP_RELAY_SECURE`          | メール利用時 | `true` でTLS接続を使用。`false` の場合はSTARTTLSを要求します。                                                                                                                                         |
| `SMTP_RELAY_USER`            | メール利用時 | SMTP認証のユーザー名。                                                                                                                                                                                 |
| `SMTP_RELAY_PASS`            | メール利用時 | SMTP認証のパスワード。                                                                                                                                                                                 |
| `SMTP_RELAY_DOMAIN_FROM`     | メール利用時 | 送信元アドレス `noreply@<ドメイン>` に使用するドメイン。                                                                                                                                               |
| `CLOUDFLARE_TOKEN`           | 任意         | `npm run dev` で使用するCloudflare Tunnelのトークン。                                                                                                                                                  |
| `LOG_DIR`                    | 任意         | ログ出力先。既定値は `logs`。                                                                                                                                                                          |
| `MEMORY_DIR`                 | 任意         | ボットのメモリ保存先。既定値は `data/memory`。ボットのメモリ設定により、無効・スレッド別・ボット全体で共有を選べます。                                                                                 |
| `TEMP_FILE_DIR`              | 任意         | OpenDAL の `fs` サービスで使う一時ファイル保存先。既定値は `data/temporary-files`。リンクは24時間有効で、ファイル上限は10 MiBです。                                                                    |
| `TEMP_FILE_STORAGE_SERVICE`  | 任意         | 一時ファイルの OpenDAL サービス名。既定値は `fs`。S3 に保存する場合は `s3` を指定します。                                                                                                              |
| `TEMP_FILE_STORAGE_CONFIG`   | 任意         | 一時ファイル保存先の OpenDAL 設定を文字列値の JSON オブジェクトで指定します。`s3` では `bucket` などの設定を渡します。                                                                                 |

`infra/compose.yaml` にはPostgreSQL、SearXNG、OpenSandboxが定義されています。オプションのサービスも起動する場合は、`infra/.env` があることを確認してください（必要であれば `infra/sample.env` をコピーします）。

```bash
docker compose --env-file .env -f infra/compose.yaml up -d
```

各連携サービスの認証情報や設定はワークスペース上で設定してください。サンドボックスプロバイダーは、対応する環境変数を設定するとUIに表示されます。

## ビルドと起動

```bash
npm run typecheck
npm run build
npm run start
```

本番サーバーにも同じ環境変数が必要です。また、初期化済みで到達可能なPostgreSQLデータベースが必要です。

### Docker

本番用イメージをビルドして起動します。

```bash
docker build -t ai-bots .
docker run --env-file .env -p 3000:3000 ai-bots
```

コンテナに本番用の `DATABASE_URL`、`CREDENTIALS_ENCRYPTION_KEY` と、利用する連携サービス固有の設定を渡してください。コンテナを更新してもメモリが残るよう、`MEMORY_DIR` に永続ボリュームをマウントしてください（例: `-v bot-memories:/app/data/memory`）。公開環境ではHTTPSを使用し、OAuthを利用する場合は `OAUTH_BASE_URL` に公開オリジンを設定してください。
